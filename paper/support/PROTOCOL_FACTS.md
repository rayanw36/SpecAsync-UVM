# Protocol facts for Section V (Gate C8, Phase 2; read-only; every row built from the gate's pre-registration and report)

**Scope and sources.** One row per gate from E0.9b to E9, plus E7-T4. E1b, E3a/E3a-2 and E3b are verification steps with committed expectations but no pre-registered sweep, and are not rows (their protocol is in `E3A_WIDTH_REVIEW.md`, `E3A2_REVIEW.md`, `GATE_E3B_REPORT.md`). Commit dates are git commit times. **The September commit clocks are not trustworthy as durations** (E4's 200-run sweep shows 7 minutes between its first and last commits), so the **order** is proved by ancestry (`git merge-base --is-ancestor <pre-registration commit> <first sweep commit>`: yes for all nine gates), not by the timestamps. Smoke and pilot rows are excluded from every analysis. Every comparison is two-sided Mann-Whitney U on process wall-clock (E5: also on demand faults), delta against the named baseline.

**Block S (E0.9b, verbatim, "Automatic stop conditions"):** "If any of these occurs, **stop the whole session immediately**: no retries, no reload, no restoration of the desktop. 1. Any new `nvidia_uvm` line in `dmesg` containing `BUG`, `Oops`, `WARNING`, `general protection`, `NULL pointer`, or `exited with irqs disabled`. Diff `dmesg` against its state before each run. 2. `rmmod` fails, or `/sys/module/nvidia_uvm/refcnt` is not 0 before a reload. 3. A benchmark hits its `timeout`. A hang can mean a dead fault-servicing thread. 4. `MemAvailable` below 6 GiB. 5. Free disk space on the results filesystem below 10 GiB. 6. The loaded srcversion differs from the one recorded in Step 0. 7. Anything that would require departing from the committed pre-registration." Implementation note: the runner applies the dmesg pattern to every new line, not only lines naming `nvidia_uvm`; a nonzero benchmark exit, failed `insmod` or failed `specasync_clear` is a stop under condition 7.

**Block E4 (verbatim):** "Any new `dmesg` line (any source) matching `BUG`, `Oops`, `WARNING`, `general protection`, `NULL pointer`, `exited with irqs disabled`, `soft lockup`, `hung_task`, or `RCU stall`; `rmmod` failure or nonzero `refcnt`; benchmark timeout; `MemAvailable` below 6 GiB; free disk below 10 GiB; srcversion mismatch; nonzero benchmark exit; parameter read-back mismatch; `specasync_ft_fast_verified != 1` on any fast = 1 load; `specasync_ft_fast_cas_giveup > 0`; `specasync_spec_region_invalid > 0`; or anything requiring a departure from the committed pre-registration. **On any of these: stop immediately.** No retries, no reload, no desktop restore."

**Block E6 (verbatim, = E5 with the threshold read-back):** E4's list with "(timestamp-based diff)" after the dmesg pattern and "parameter read-back mismatch (including `uvm_perf_prefetch_threshold`)", "**any departure from this pre-registration**"; "On any stop: stop immediately, no retries, leave the machine as it is, record the evidence, commit locally, and write the Phase 7 summary." E7 = E6; E8 = E7 plus a nonzero benchmark exit including a checksum mismatch; E9 = E8 plus nsys failure; E7-T4 = E7 plus the two additions in its row. The wall-clock outcome is process wall-clock `time.monotonic_ns()` around `timeout T setarch -R <bench>` in every gate.

## Table 3. Statistics helpers actually used

| function | file:line | computes |
|---|---|---|
| `mwu(x, y)` | `tests/e09b_analyze.py:33` | two-sided Mann-Whitney U (`scipy.stats.mannwhitneyu`), `method="exact"` when the pooled values have no ties, else `"asymptotic"` |
| `holm(ps)` | `tests/e09b_analyze.py:39` | Holm-Bonferroni step-down: threshold `ALPHA / (m - rank)` in order of p; significance holds while every earlier test is significant (`ALPHA = 0.05`, `:16`) |
| `tukey_keep(xs)` | `tests/e09b_analyze.py:27` | Tukey 1.5 x IQR fences (inclusive quartiles); used only for the "without outliers" secondary analysis, never to remove a run from the primary one |
| `compare(base, arm)` | `tests/e09b_analyze.py:49` | medians, delta (s and %), U and p, Cohen's d (pooled SD), `mde_s = Z_MDE * sd`, `mde_bonf_s = Z_MDE_BONF * sd`, with `sd = sqrt(var1/n1 + var2/n2)` |
| MDE constants | `tests/e09b_analyze.py:17-18` | `Z_MDE = 1.959964 + 0.841621` (two-sided alpha 0.05, power 0.80); `Z_MDE_BONF = 2.955167 + 0.841621` = **alpha 0.05/16** (hard-coded; catalog #27) |
| family-alpha override | `tests/e4_analyze.py:21` (`2.991316 + 0.841621`, alpha 0.05/18); `tests/e5_analyze.py:28` (`2.393980 + 0.841621`, alpha 0.05/3) | E4 and E5 overwrite `H.Z_MDE_BONF` for their own families; their `mde_bonf_s` is correct (`MDE_AUDIT.md`). E6 does not |
| `mde_family(c, m)` | `tests/e7_analyze.py:56-58` | `(norm.ppf(1 - 0.05/(2m)) + 0.841621) * sd`, `sd = mde_s / Z_MDE`; used by E7, E8, E7-T4 (`mde_family_s`, `mde_family_pct`) |
| `holm_apply(cs)` | `tests/e7_analyze.py:70-74` | applies `H.holm` over one family's list of comparisons |
| D(t) | `tests/e5_analyze.py` (header) | `D(t) = 1 - median(demand faults C7W512-t) / median(demand faults C0-t)`; verdict rule thresholds 0.25 and 0.75 x D(51) |
| delta convention | `tests/e7_analyze.py` / `e8_analyze.py` headers | `(arm - baseline) / baseline`; negative = the arm (lower threshold) is faster |
| positive controls | `e6_analyze.py --control`, `e7_analyze.py --control`, `e8_analyze.py --control`, `e9_analyze.py --control`, `t4/e7t4_analyze.py --control`; E4 and E5 gained theirs in C8 phase 6 | see `results/analysis/REPRODUCE.md` |
